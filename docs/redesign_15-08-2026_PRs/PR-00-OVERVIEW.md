## 1. What we are building and why

The current site (Jekyll / Beautiful Jekyll theme) presents Miroslav as
*"a PhD student who writes papers and coaches floorball."*

The redesigned site must present him as:

> **An applied computer-vision scientist who ships: first-author CVPR/ICCV research, systems
> that run in production and in the field, and a track record of leading people — currently
> finishing a PhD.**

**Primary audience (locked by Miroslav):**

1. **Applied scientist / research scientist roles in industry** — main target
2. **Applied ML/CV engineering roles** — equally main target
3. **Contract / consulting work** — mention briefly, one sentence, not a pitch
4. Academic postdoc — *not* a target; do not write the site for hiring committees

**Consequences for every PR:**

- Research and engineering evidence carry equal weight. A paper and a deployed system are
  presented with the same visual prominence.
- Career stage is stated honestly ("PhD candidate"), never inflated, never apologised for.
- The personal material (coaching, mountains, books, travel) stays on the site because it makes
  him human — but it lives on `/about` and `/coaching`, **not** in the top-level pitch. The site
  never markets him as a coach.
- Copy is factual and specific. Concrete numbers and named institutions, no adjectives that
  cannot be checked. See §7.

## 6. Shared working conventions (apply to every PR)

**Branch & merge**

- Branch from `redesign`, name it `redesign/pr-NN-slug`, open the PR against `redesign`.
- Never commit to `master`. Never modify files in `docs/` except to tick a status box.

**Tooling**

- Node 20+, npm (lockfile committed).
- `npm run dev` / `npm run build` / `npm run preview`; `npx astro check` must be clean.
- Prettier with `prettier-plugin-astro`; run `npm run format` before committing.

**Definition of done for every PR**

1. `npm run build` succeeds and `npx astro check` reports 0 errors.
2. New/changed pages verified at **320 px, 768 px, 1440 px** viewport widths.
3. New/changed UI verified in **both light and dark theme**.
4. Keyboard reachable, visible focus ring, no information conveyed by hover alone.
5. No new client-side JavaScript beyond what the PR explicitly authorises.
6. Every factual claim traceable to §8 of this file. **Do not invent facts, numbers, dates,
   affiliations or awards.** If something is missing, use the fallback copy the PR provides
   and list the gap in the PR description.
7. PR description lists: what was built, screenshots (light + dark), open flags.

**Code conventions**

- One component per file in `src/components/`, PascalCase, typed `Props` interface exported.
- Component-scoped styles inside `.astro` files; only genuinely global rules live in
  `src/styles/`.
- Use design tokens (CSS custom properties). **No hard-coded colours, radii or spacing values**
  outside `tokens.css`.
- Semantic HTML: `header/nav/main/section/article/aside/footer`, one `<h1>` per page, no skipped
  heading levels, no fake headings.
- Images through `astro:assets` (`<Image>`/`<Picture>`) with explicit dimensions and real `alt`
  text; decorative images get `alt=""`.
- All motion behind `@media (prefers-reduced-motion: reduce)`.

## 7. Voice and copy rules

- Short sentences. Concrete nouns. No buzzwords, no "passionate", no "cutting-edge".
- Prefer *"First-author papers at CVPR 2025 and ICCV 2025"* over *"published at top venues"*.
- Prefer *"Runs at under 0.5 s latency on six 4K cameras"* over *"high-performance system"*.
- Never justify body text (`text-align: justify` is banned — the current site uses it everywhere).
- Use "I" — first person, plain, unhyped.
- Czech names and diacritics rendered correctly: Miroslav Purkrábek, Jiří Matas, Sokol Královské
  Vinohrady, Jan Skvrna.
- Awards belong to the work, not to the ego: state venue, year, award name, nothing more.
